# 販売図面を作る AI エージェントへの指示（Codex / Claude Code 共通）

このフォルダで作業する AI エージェントは、営業担当者と対話しながら、新築戸建の販売図面（顧客向けの中面）を作る。外注に出していた「原稿 → 完成版」の工程を社内で行うのが目的。**ラフ → 逆質問 → 文章の候補 → 仕上げ**の順に進め、一度に完成版を作ろうとしない。

## 1. 守ること（例外なし）

1. **値を推測で埋めない。** 資料に書いてある値か、営業が答えた値だけを JSON に書く。分からなければ空欄のままにし、逆質問で聞く
2. **拾った値の出どころを残す。** 物件フォルダの `sources.md` に「項目・値・資料名・ページ」を1行ずつ書く
3. **文章には根拠を付ける。** キャッチ・サブコピー・特長ラベル・間取りコメントは `{"text": "...", "basis": ["項目のパス", ...]}` の形で書く。根拠のない文は書かない
4. **規約の禁止語を使わない。** 完全・完璧・絶対・万全・日本一・業界一・超・当社だけ・最高・最高級・極・特級・格安・激安・バーゲンセール・特選・厳選・完売 など（不動産の表示に関する公正競争規約 第18条）。点検で止まったら言い換える
5. **最終判断は人がする。** 文章は候補を出して営業に選んでもらう。`final` の PDF は、営業が中身を確認するまで「完成」と呼ばない
6. **実物件のデータ・画像をこのリポジトリに入れない。** 物件フォルダはリポジトリの外に置く（下の 2 章）。commit・push は指示があるときだけ

## 2. 物件フォルダ

リポジトリの外に、1物件1フォルダで作る。

```
~/販売図面/<YYYYMMDD>_<物件名>/
├── 資料/            営業から受け取った PDF（仕様書・実行図・求積図・電気図・パース・確認済証など）
├── property.json    物件データ（prototype/sheet/property.schema.json の形）
├── sources.md       拾った値の出どころ
├── annot_1F.json …  間取り図の書き足し（車・コメント）
├── floorplans/      間取り図の PNG・SVG
└── out/<YYYYMMDD>/  版ごとの出力（naka.html・naka.pdf・report.md・report.json）
```

価格や販売状況が変わったら、`property.json` を直して `out/` に新しい日付で出し直す（前の版は消さない）。

## 3. 手順

スクリプトは `prototype/` にある。Python は依存を入れた環境（`prototype/requirements.txt`）で実行する。以下 `$S` は `Sales Sheet Template/prototype`、`$P` は物件フォルダ。

### 手順 1: 資料の判定
```bash
python $S/s6_triage.py $P/資料
```
- 間取り図に使うページ（`use`）と階を確認する。`use` が無い階は、スキャン画像しかないということ。営業に「CAD の PDF（クロス貼り分け図・電気図・平面詳細図など）があるか」を聞く

### 手順 2: 間取り図
```bash
python $S/s6_floorplan.py --pdf <PDF> --page <ページ> --floor 1F --out $P/floorplans/1F.png --svg $P/floorplans/1F.svg
```
- 出力の室名・帖数が資料と合っているか、画像を見て確かめる。販売図面の間取り表記（例 3(4)LDK+S+3バルコニー）と部屋数が合わなければ営業に確認する（過去に、完成版の帖数の誤りがこれで見つかった）

### 手順 3: 値の抽出
- 仕様書・求積図・確認済証などから値を拾い、`property.json` を埋める。項目の意味と規約上の必須は `03_S13物件概要_項目定義.md`、スキーマは `prototype/sheet/property.schema.json`
- 取り違えやすい値:
  - 建ぺい率・容積率は**用途地域の指定値**を書く（求積図の実際の値 51.11% などではない）
  - 建物面積は延床面積。車庫があれば車庫の面積も書く
  - 図面の「納戸」は居室に数えず、間取りでは「S」
  - 構造（木造など）と建築確認番号は設計図書に無いことが多い → 確認済証か逆質問

### 手順 4: ラフと逆質問
```bash
python $S/sheet/build_sheet.py --data $P/property.json --out $P/out/<日付> --stage rough
```
- `report.md` の error を上から順に、**1回に1問ずつ**営業に聞く。資料を読めば分かることは聞かない
- 選択肢がある質問は選択肢を示す（例: 引渡し「即時／◯年◯月以降／相談」）
- 答えを JSON に書いたら、もう一度 `rough` を実行して、error が減ったことを確かめる

### 手順 5: 文章の候補
`property.json` の `copy_candidates` に候補を書き、`rough` を実行して `report.md` の「文章の候補」の表を営業に見せ、番号で選んでもらう。

| 種類 | 数 | 長さ | 書き方 |
|---|---|---|---|
| キャッチ | 3案 | 1行28字以内・2行 | 立地の強み＋建物の強み。赤くする語を1〜2個（`highlight`） |
| サブコピー | 3案 | 8〜16字 | 「〜◯◯〜」の形 |
| 特長ラベル | 10個 | 4〜15字 | 設備・間取り・立地の事実。例「LDK17.0帖」「食器洗い乾燥機（深型）」 |
| 間取りコメント | 階ごとに2〜4本 | 1行16字以内・2行 | 部屋の使い方。例「客間としても利用可能な\n6帖のサービスルーム」 |

- 候補を書く前に、営業に「この物件でいちばん推したい点」を1問だけ聞く
- 数値は必ず JSON の値から取る（点検で照合される）
- 選ばれたものを `catch`・`subcopy`・棟の `features` に移す。間取りコメントは `annot_<階>.json` に書き（`prototype/annot_example.json` の形）、手順 2 の `--annot` を付けて間取り図を作り直す

### 手順 6: 仕上げ
```bash
python $S/sheet/build_sheet.py --data $P/property.json --out $P/out/<日付> --stage final
```
- 終了コード 2 なら error が残っている。`report.md` を見て手順 4 か 5 に戻る
- PDF ができたら、営業に次を確認してもらう: 価格・面積・号棟、キャッチと特長ラベル、間取り図の室名と帖数、物件概要の段落、写真のキャプション

## 4. 表記ルール（スクリプトが自動でそろえるもの）

- 坪 ＝ ㎡×0.3025 を小数第2位で切り捨て
- 徒歩 ＝ 道路距離 80m で1分、端数は切り上げ。距離を聞き、分は計算する
- 価格は税込（新築）。土地価格は非課税
- 可変間取りは `3(4)LDK` と書く
- 規約の基準は「パンフレット等」（引渡し可能年月・全戸の価格と面積・地番・建築確認番号が必須）

## 5. 今できないこと

表紙、地図、区画図、設備アイコンの画像、家具のイラストと家事動線の矢印は、まだ自動で作れない。紙面には「未設定」の枠が出る。営業には「この部分は従来どおり用意が必要」と伝える。
